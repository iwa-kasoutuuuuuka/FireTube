# Android 版 → Vega 版 移植仕様メモ

Android 版 `app/src/main/java/com/firetube/tv/` の取得層を読んで整理した、Vega 版 (TypeScript) の実装仕様。
**Android 版で動いている事実**と**Vega で未検証の事項**を分けて書く。コードは写さず仕様のみ移す。

## 1. 取得経路の優先順位 (Android 版の実績)
`InnerTubeClient.extractStreamInfo` のフォールバック順:
1. `IOS_KIDS` と `VISIONOS` を並列に叩き、最初に有効なストリームを返した方を採用 (残りはキャンセル)
2. `IOS` (embedded 指定: 音楽 PV / ログイン要求の救済)
3. `ANDROID_KIDS`
4. 標準 `IOS`
5. 最終的に NewPipeExtractor / Piped (Vega 版では NewPipe は使えない → Piped のみ)

要点:
- エンドポイントは `POST https://www.youtube.com/youtubei/v1/player`、本文は `{ context: { client: {clientName, clientVersion, ...} }, videoId }`。
  clientName / clientVersion / User-Agent の組は `InnerTubeClient.kt` 冒頭の定数を参照 (例: `IOS` 21.03.2)。
- 組み合わせは YouTube 側の変更で頻繁に壊れる。**定数は設定として外出しし、更新しやすくする**。
- 取得できるのは主に **HLS (`hlsUrl`)**。Android 版は HLS を基本にし、分離 DASH (映像+音声) は別経路。
  → Vega 版の最初の再生目標は **HLS 1 本再生** が最短 (MSE で DASH を自前合成するより低リスク)。HLS 対応は未検証。
- 一覧系: `trending` / `search` / `browse` (チャンネル) / `next` (関連動画) も同じ `youtubei/v1` の WEB コンテキスト。
  レスポンスは `videoRenderer` / `lockupViewModel` / `playlistRenderer` / `shortsLockup` が混在し、
  再帰探索 (`findVideoRenderersRecursive`) で拾っている。構造変更に強いよう再帰探索で実装する。
- visitorData を事前取得して使い回す (`preFetchVisitorData`)。

## 2. 再生 (googlevideo.com CDN)
Android 版 `GoogleVideoDataSource` が解決している問題:
- googlevideo.com は **Range なし / 終端なし (`bytes=0-`) / 範囲超過のリクエストに 403** を返す。
- 対策: URL の `clen` (または `Content-Range`) から全長を得て、**512KB の有界チャンク (`bytes=START-END`)** で順次取得。
- HLS プレイリスト (`.m3u8`, `/manifest/`, `playlist_type`, `hls_variant`) は Range 分割せずそのまま取得。
- UA は固定のデスクトップ Chrome 風。403 検出時は上位に通知して別経路へフォールバック。

Vega 版への含意 (未検証):
- MSE で映像/音声を別 SourceBuffer に積む場合、`fetch` + `Range` で同じチャンク取得を自前実装する必要がある。
- HLS を `<video src>` に直接渡せるなら、チャンク取得はプレイヤー任せで済む可能性があるが、403 の扱いは要確認。
- React Native の `fetch` で `User-Agent` / `Range` ヘッダを自由に設定できるかを最初に確認する。

## 3. 補助 API (HTTP のみ・最初に移植する)
| 機能 | 仕様 |
| :--- | :--- |
| SponsorBlock | `GET https://sponsor.ajay.app/api/skipSegments?videoID=<id>&categories=["sponsor","intro","outro","selfpromo","interaction"]`。404 は「区間なし」の正常系。応答 `[{segment:[start,end], category, UUID}]`。秒→ms 変換して再生位置と比較 |
| Return YouTube Dislike | `GET https://returnyoutubedislikeapi.com/votes?videoId=<id>`。応答 `{id, likes, dislikes, rating, viewCount}`。直近 50 件をメモリキャッシュ |
| Piped | 複数インスタンスを順に試す (`PipedApiClient.kt` の一覧を参照)。トレンドは `region=JP` |

## 4. データモデル (TypeScript へ)
```ts
interface VideoItem { id: string; title: string; uploaderName: string; uploaderUrl?: string;
  thumbnailUrl: string; durationSeconds: number; viewCount: number; uploadDate?: string }
interface VideoStream { url: string; resolution: string; format: string; isVideoOnly: boolean; bitrate: number }
interface AudioStream { url: string; format: string; bitrate: number }
interface SubtitleTrack { url: string; languageName: string; languageCode: string; isAutoGenerated: boolean }
interface StreamInfoData { videoId: string; title: string; uploaderName: string;
  videoStreams: VideoStream[]; audioStreams: AudioStream[]; hlsUrl?: string; dashUrl?: string;
  subtitles: SubtitleTrack[]; durationSeconds: number }
interface SponsorSegment { segment: [number, number]; category: string; UUID?: string }
interface DislikeVotes { id: string; likes: number; dislikes: number; rating: number; viewCount: number }
```
`VideoItem` の一覧フィルタ規則: id が空・タイトルが空 / "No title" / "Unknown Title" /
「非公開動画」「private video」「deleted video」「削除された動画」を含むものは除外。`id` が `__` で始まるものは UI 用の特殊カード。

## 5. 移植順序
1. 型定義 + SponsorBlock + RYD (ネットワークの `fetch` が使えるかの確認も兼ねる)
2. InnerTube `player` で `hlsUrl` を取得 → 固定 ID で Vega Media Player に渡して再生できるか
3. 一覧 (`trending` / `search`) と UI
4. 403 フォールバック、Piped、字幕、画質切替
